# Fractal for Codex

Run `node <this-skill-directory>/runtime.mjs` once. It returns the live checkout,
version, axis paths and Herdr capability in native paths, including on Windows.
Read the returned spec and the relevant axis in full, verbatim; code when unsure.
Use the user's task as the intent. The parent plans and owns the verdict; add a
planning child only for uncertain decomposition or a requested plan challenge.
User scope and existing authorization govern; a framework step adds no authority.

The axis's tool bindings are defaults for its original harness. In Codex:

- Use the session's file, shell and web tools. Keep the shared tracker, hooks and
  meter when applicable. For Code work, use `node <home>/cmd/init.mjs <repo>` for
  missing project setup; preserve existing project hooks. Research uses the
  project's actual data, runner and verification commands, not the example desk.
- Delegate only useful independent work. If Herdr is available, read its returned
  skill and use its launcher for the whole lifecycle. Visible Herdr work requires
  that binding; report a missing binding rather than substituting another harness.
  Outside Herdr, use native Codex agents when available and authorized. Without a
  runner, the parent can work; report any independent verification still missing.
- Herdr roles: scout for local facts, researcher for sources, worker for changes,
  reviewer for verification; general for lightweight synthesis. Use its role
  defaults, escalating only for a concrete task need. Fractal lead and senior are
  responsibilities, not extra installed Codex roles or mandatory children.
- A child's brief names the question, owner, allowed files, budget, artifact,
  home and axis. Use `<home>/roles/fractal-<role>.md`: scout/researcher map to
  scout, worker to worker, reviewer to verifier, planning to lead, reduction to
  senior; general synthesis needs no extra role. Include the role body and the
  spec/axis text it requires verbatim.
  Follow-ups carry changed claims, files and counterexamples, not the whole brief;
  each names the item it amends and what is still open, so steering does not
  replace the objective. A final names the item it closes; the artifact, not the
  paragraph, proves it.
- Collect the deliverable and inspect its evidence before judging. A progress
  message, `blocked` state or notification is not completion. Use bounded waits
  while doing useful parent work; on timeout, read the plain result and the
  artifact before reporting what remains. Keep a failed
  verifier available for the focused fix, then collect and stop owned children.

The installed folder links to the checkout; updates there are live. No Codex
configuration, model setting, permission profile or Herdr implementation is changed.
